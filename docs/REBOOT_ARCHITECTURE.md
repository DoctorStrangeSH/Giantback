# Giantback Reboot — Target Architecture

## Решение ADR-001: постоянный архипелаг

**Статус:** принято для Reboot 1.0.

- Острова статичны и не перемещаются по карте.
- Домашний остров — постоянная персональная территория игрока.
- Новые территории открываются через серверно-проверяемое строительство мостов и сюжетные открытия.
- Общие приключенческие биомы не принадлежат одному игроку.
- Посещение городов друзей использует явные права гостя.

## Персональные города

Текущий прототип PersonalCities накладывает персональные визуальные модели друг на друга и скрывает их через LocalTransparencyModifier. Это временный blockout, не целевая архитектура.

Целевая система:
- сервер выдаёт игроку отдельный фиксированный plot/island instance;
- острова разных игроков имеют разные координаты и стабильный OwnerUserId;
- модель и данные города принадлежат профилю;
- гость получает доступ только после проверки разрешения владельца;
- клиентское скрытие UI/моделей не является защитой;
- сервер проверяет владельца, расстояние, доступность площадки, цену и состояние объекта для каждого изменения.

Для первого публичного теста допускается посещение острова друга, если владелец находится в том же сервере. Межсерверные и офлайн-визиты — отдельная задача после стабилизации 1.0.

## Сервисы

Целевая структура:
- ProfileService — загрузка, сохранение, миграции, блокировка профиля;
- InventoryService — предметы, ресурсы, валюты и лимиты;
- CityService — участок, расширения и права гостей;
- BuildService — размещение, перемещение, удаление и сохранение построек;
- BridgeService — материалы, состояние мостов и открытие островов;
- FarmService — культуры, рост, полив, сбор и улучшения;
- CompanionService — коллекция, активный спутник и способности;
- WorldService — биомы, ресурсы, точки интереса;
- DungeonService — группы, комнаты, босс и награды;
- SocialService — посещения и совместные действия;
- MonetizationService — passes, developer products и receipts.

Сервисы выделяются по мере реализации; не создавать пустые абстракции без работающего использования.

## Данные профиля

Следующая миграция: schemaVersion 5. Она должна:
- сохранить текущую коллекцию, материалы и прогресс, где это возможно;
- преобразовать legacy city/farm поля в новую модель острова;
- не переносить старые флаги путешествия как состояние мира;
- иметь безопасные значения по умолчанию;
- быть идемпотентной и покрытой тестами.

Рекомендуемая структура:
- schemaVersion;
- currencies;
- inventory;
- companions.owned;
- companions.equipped;
- city.level;
- city.expansions;
- city.bridges;
- city.buildings;
- farm.level;
- farm.plots;
- world.discoveries;
- dungeons.progress;
- settings.

Нельзя менять production DataStore до тестирования миграции на отдельном Studio store.

## Remote security

Все действия, меняющие профиль, валидируются сервером:
- действие разрешено для игрока;
- объект принадлежит игроку или доступен по правам гостя;
- дистанция до интерактива допустима;
- цена и предметы рассчитываются сервером;
- состояние не изменилось между проверкой и применением;
- частота запросов ограничена;
- повторный запрос не дублирует награду.

## Legacy removal plan

Удалить из целевого игрового цикла:
- управление штурвалом и движение Мохоспина;
- обязательное перемещение между двумя стоянками;
- временную модель двух рощ как единственных зон;
- перекрывающиеся PersonalCities;
- старый HUD с маленькими карточками и непонятной коллекцией.

Legacy-данные не удалять без миграции и проверки сохранений.
