## Получить актуальную игру

1. Открой [GitHub Actions](https://github.com/DoctorStrangeSH/Giantback/actions/workflows/validate-place.yml) и выбери **последний успешный запуск ветки `main`**. С 23 ноября 2026 игровые исходники включены в `main` через [PR #8](https://github.com/DoctorStrangeSH/Giantback/pull/8); старые PR #1/#7 не являются источником актуальной сборки.
2. Внизу запуска скачай артефакт `Giantback-visual-build`. Внутри — `Giantback.rbxlx` и исходные ресурсы. Не путай файл сборки с исходными OBJ.
3. Распакуй архив. Открой `Giantback.rbxlx` через **Roblox Studio → File → Open from File**.
4. Если Roblox Studio предлагает сохранить копию, используй отдельную тестовую версию/файл. **Не публикуй поверх рабочей игры до приёмки.**

## Быстрая диагностика (без изменения мира)

Скрипт: `tools/roblox/studio_playtest_preflight.luau` (в архиве сборки и в GitHub).

1. В Roblox Studio открой **View → Output** и **View → Command Bar**.
2. **В режиме Edit** вставь весь текст скрипта в **Command Bar** и выполни. Он покажет `PASS`, `FAIL`, `REVIEW` и `PENDING` для скриптов, модулей, мира и резервных моделей питомцев.
3. Нажми **Play**, дождись появления персонажа. Переключи Command Bar в **Server** context (если Studio предлагает выбор контекста) и выполни тот же скрипт ещё раз.
4. Убедись, что в Output есть `SUMMARY` и отметки `PlayerIslands`, `HomeIsland_<UserId>`, `HomeSpawn`, `Ready`. Если `Ready` ещё не установлен, дай игре закончить загрузку и повтори проверку.
5. `PENDING` не считается успехом: это означает, что режим Edit или текущая конфигурация не позволяет подтвердить пункт. `REVIEW` означает обязательную ручную проверку.

Скрипт только читает структуру. Он **не включает** готовность ассетов, **не меняет** DataStore, **не сохраняет** и **не публикует** игру.
